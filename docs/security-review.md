# 安全审查与验证

对象：SilentDeep/KMCounter 原版源码及 Windows 包、此 fork 的后台版源码和重新构建程序。
检查未将个人统计、凭据或日志发送到 GitHub；Git 忽略个人数据、构建环境和本地测试目录。

## 原版发现

- 三个 Python 源文件及页面请求中未发现主动上传、遥测、剪贴板、截图或远程命令执行代码。
  使用屏幕尺寸接口不等于截屏。Plotly 的地图和云导出代码存在于通用库中，原页面没有启用。
- 记录每分钟字符次数和点击位置并明文保存；JSON 字段顺序还保留不同键的首次出现顺序。
  这些数据不是完整输入文本，但可能泄露短输入组成和使用习惯。
- `/end_program` 原先无令牌和来源检查，可被外部页面发起 POST，直接退出而不走保存流程。
- 逐事件由不同监听线程复制写入同一个 JSON 文件，不是原子替换；可能冲突、截断或覆盖。
- 原 Windows 包使用 Python 3.9 和 Werkzeug 3.0.4，落在已公布的 Windows 路径处理漏洞范围内。
  https://github.com/pallets/werkzeug/security/advisories/GHSA-f9vj-2wh5-fj8j
  https://github.com/pallets/werkzeug/security/advisories/GHSA-g6x2-hccm-hh4m
- 旧 exe 未签名，解压文件与仓库压缩包中的 exe 一致；模板与图表脚本也一致，换行格式不同。
  此检查不等于逐个验证原二进制内的全部依赖；交付使用重新构建程序。

## 后台版处理

- 规范按键、聚合统计、排序字段，不保存逐次输入事件；不增加截图、剪贴板或窗口追踪。
- 线程锁、五秒定期写盘、同目录临时文件加 `os.replace`；暂停和正常退出前保存，失败显示错误并保留内存。
- 当前用户普通权限运行；登录启动可从托盘取消。数据目录使用 Windows Known Folder API。
- 本机独占绑定 127.0.0.1:5000，绑定成功后才启动输入监听；Windows 命名互斥量阻止重复实例。
- Host、Origin、Sec-Fetch-Site 校验；控制操作还需要随机令牌。不添加 CORS，不在访问日志记录统计或令牌。
- 本地 Plotly 4.2.0 cartesian 包，不包含地图模块；禁用云端导出，CSP 限制外部连接和资源。
  脚本来源与 SHA256 见 `static/plotly-provenance.json`。
- Python 3.13.18、Werkzeug 3.1.9 及其余运行依赖锁定版本和下载哈希。运行依赖的 pip-audit
  结果为未发现已知漏洞，详见 `dependency-audit.json`；这不是对未知漏洞的保证。

## 已验证及边界

- 自动测试覆盖规范化、并发、跨日、重启、损坏文件、写盘失败、导入重试、控制保护、空数据和单次事件。
- 真实 Chrome 测试使用合成聚合数据，验证两类热力图、实时刷新、历史范围、暂停恢复和正常退出。
  阻断所有外网请求的情况下测试通过，观察到的页面请求全部指向 127.0.0.1，无页面脚本异常。
- 打包程序已测试真实 F24 键捕获、暂停、恢复、五秒保存、无控制台和重复启动。
  观察该进程的 TCP 端点，只发现本机网页监听与 Waitress 内部 loopback 连接。
- 真实重新登录后的自启动尚未验证；不会自动注销或重启用户电脑。
- loopback HTTP 在本机账户之间共享；其他本机账户或程序仍可能读取统计网页、令牌和接口。
  同一 Windows 用户或管理员下的程序还可读取明文文件；后台版不隔离恶意本机程序或本机账户。
